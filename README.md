# SQL Trainer

Кабинет домашних заданий по SQL. Студент пишет запрос, запускает его на учебной базе и сдаёт на проверку. Преподаватель видит баллы, может поправить оценку и выгрузить ведомость.

Учётки, черновики, попытки и оценки хранятся в SQLite кабинета. Учебная PostgreSQL открыта только на чтение: кабинет не пишет в неё и не хранит там свои данные.

## Студент

На главной лежат песочница и карточки домашних заданий: баллы, прогресс, мягкий и жёсткий срок. В задаче слева список всего задания, справа условие и редактор. Черновик сохраняется сам. Запуск показывает результат, проверка ставит балл.

Вход по логину и паролю. Почта не нужна. В профиле меняются ФИО и пароль.

Если строки не сошлись с эталоном, студент видит номер первой такой строки. Сами ожидаемые значения ему не показываются.

## Преподаватель

На экране входа две отдельные плашки. Ассистент вводит свой логин и пароль: если прав ассистента нет, вход не открывается. Администратор вводит те же логин и пароль и ещё ключ. Ключ задаётся в `CABINET_ADMIN_TOKEN` и в форме так не называется. Отдельной роли «суперадминистратор» нет: администратор и есть тот, кто публикует курс, видит журнал и выдаёт права.

Ассистент – обычная учётная запись студента. Доступ включается в разделе «Права», отдельный пароль для роли не создаётся. Ассистент видит студентов, историю, выгрузки и может поставить ручную оценку.

Ручная оценка заменяет более ранний результат. Если студент позже сдаёт проверку с большим баллом, учитывается уже она. На карточке задачи видны сырые баллы. Штраф за опоздание считается в выгрузке, не на карточке.

## Баллы и сроки

У каждого домашнего задания есть мягкий срок и жёсткий. Общий `hard_deadline` в начале манифеста – срок по умолчанию. Свой срок задания его перекрывает.

До жёсткого срока проверка открыта. После него обычная сдача получает 0 баллов, пока преподаватель не откроет проверку этому студенту и не напишет причину.

Штраф начинается после мягкого срока. Начавшиеся сутки считаются целиком. Формула считает только арифметику, без произвольного кода. Переменные: `score`, `late_days`, `period_days`, `multiplier`, `max_penalty_fraction`.

```json
{
  "formula": "score * multiplier ** (late_days / period_days)",
  "period_days": 7,
  "period_multiplier": 0.8,
  "max_penalty_fraction": 0.4,
  "minimum_score_fraction": 0.6,
  "round_digits": 2,
  "rounding_mode": "half_up"
}
```

`period_multiplier` попадает в формулу как `multiplier`. Итог не опускается ниже `score * max(1 - max_penalty_fraction, minimum_score_fraction)`.

Ведомость берёт текущий балл кабинета. Выгрузка вех перечисляет каждое сырое достижение и штраф по нему. Максимум по вехам может показать старый результат, который ручная оценка уже заменила. Для итоговой оценки нужна ведомость.

## Запуск

```sh
cd cabinet-app
cp .env.example .env
make setup
make manifest-check
make dev
```

В `.env` нужны read-only `CABINET_LEARNING_DSN` и длинный случайный `CABINET_ADMIN_TOKEN`. Файл остаётся в этой папке и в git не попадает. `CABINET_ADMIN_NAME` необязателен: это имя для действий по заголовку с ключом, по умолчанию «Администратор».

Кабинет открывается на `http://127.0.0.1:8000`. Описание API: `http://127.0.0.1:8000/docs`. Остановка локального сервера: `Ctrl-C`.

Локальная база и копии лежат в `cabinet-app/var/`. Контейнер: `docker compose up --build -d`, остановка без удаления данных: `docker compose down`.

## Курс

Сначала кабинет читает последнюю опубликованную версию из SQLite. Если публикации ещё не было, берётся файл: в проде это `/data/manifest.json`, локально – `manifest.course.json` рядом с приложением, если он есть.

Образ Docker этот файл не копирует. В `.gitignore` он указан. Пока старая копия числится в индексе git, публичный репозиторий её ещё отдаёт. Убрать из индекса, не стирая файл с диска:

```sh
git rm --cached manifest.course.json
```

`manifest.example.json` остаётся в git как короткий пример без боевых ответов.

Текущий курс: четыре задания, мягкий срок `2026-09-25 23:59`, жёсткий `2026-10-10 23:59`, часовой пояс `Europe/Moscow`. Сроки живут в манифесте. Публикация из панели «Манифест и правила» выполняет эталоны на PostgreSQL и сохраняет их результаты в новой версии. Старые попытки при этом не переписываются.

## Сохранность

Каждый день делается проверенная копия SQLite, хранятся последние 7 дней. Копии лежат на том же диске, что и база. От потери самого диска защищает только копия вне машины, её по-прежнему снимают вручную.

Восстановление локальной копии, приложение должно быть остановлено:

```sh
make restore BACKUP=/path/to/cabinet-YYYYMMDDTHHMMSSZ.sqlite3
```

## Перед изменением

```sh
make check
make manifest-check
node --check cabinet/static/app.js
node --check cabinet/static/sql-editor.js
```

`make check` гоняет линтер, тесты кабинета и тесты интерфейса. Учебная PostgreSQL для этого не нужна: тесты подменяют исполнение SQL. Публикация курса и ручной прогон запросов уже требуют живой базы. Пароль роли владельца базы для этого не используют.
